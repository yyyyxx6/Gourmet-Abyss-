# Timer 第一批实施记录

日期：2026-09-08。目标：为死亡掉落、舔包和结算界面提供真实库存、本局统计与安全的资源收取基础。

## 已完成

- 食材按占格背包收取；木材等采集物独立计数、不占格；金币和家具保留永久库存路径。
- `InventorySnapshot` 保留所有已解锁格子和空格，排除锁定预览格，结果不可变。
- `InventoryPacking` 先为全部类型补已有同类堆叠，再按调用者提供的优先级分配空格，返回实际接收/剩余清单。不提供价值函数时仅作稳定类型排序，未擅自定义食材价值。
- `InventoryManager` 增加快照读取/应用、部分添加和批量添加接口。应用前验证完整布局，不通过时不改库存。
- `LootCollector` 按实际装入量减少场景掉落物数量。满包或竞争最后容量时，未装入部分保留并重试；普通掉落物原有超时消失规则仍生效。
- 采集物入永久库存按实际到账量扣除本局袋；重复提交不重复到账，仓库容量不足则保留余量。
- 新局开始前处理上局待入库余量，仍放不下时拒绝出发且保留选关/角色状态，避免清空未到账资源。
- `RunSessionData` / `RunSessionManager` 接入关卡开始和完成、有效游玩时长、实际采集量、真实怪物击杀、首次菜谱/宠物解锁、食材净变化。
- 完成结果只生成一次，结果与后续库存变化隔离；第二局保留食材基线、清零当局统计。破坏采集物不算怪物击杀。
- 原红色局内袋调试层默认关闭；显式启用时仅在编辑器/开发构建显示采集物本局和永久总量。

## 后续可调用接口

项目脚本目录：`extraction-shooter/UnityProject/ExtractionShooter/Assets/Scripts`。

| 接口 | 用途 |
| --- | --- |
| `InventoryManager.CaptureInventory()` | 捕获全部已解锁槽位 |
| `CaptureIngredientInventory()` | 保留布局、仅包含正式食材，供净变化及结算使用 |
| `ApplyInventorySnapshot(snapshot)` | 校验通过后一次应用槽位数据 |
| `AddItemPartial(type, amount)` | 返回实际加入数量 |
| `AddItems(requested, priority)` | 批量装载，返回最终快照及接收/剩余清单 |
| `AddRunGathered(type, amount)` | 无格采集物入本局袋并记录实际采集量 |
| `CommitRunGatheredToPermanent()` | 只提交仍在本局袋内的余量，按实际到账核销 |
| `RunSessionManager.BeginRun(levelId)` | 记录食材基线、已解锁菜谱/宠物并开启新局 |
| `CaptureCurrentResult()` | 活动局只读预览 |
| `CompleteRun()` / `LastResult` | 冻结并保留本局结果，重复结束返回同一结果 |
| `LevelManager.TryEnterLevel(sceneName)` | 返回是否真正开始进入，选关在成功后才禁用角色/关闭面板 |

`RunSessionManager` 随 LevelManager 初始化，无需手动给原场景添加组件。旧食材袋 API 保留兼容包装，实际食材不会再进入无格袋。
