# Timer 第二批：结束流程与基础结算界面

日期：2026-09-09。

这是第二批的实现记录；后续第三批已将临时全损替换为默认 10% 保留与死亡箱，最新行为见[第三批记录](timer-batch3-implementation.md)。

## 已实现行为

- 死亡和撤离共用 `RunSessionManager.TryEndRun`。一局只接受一次结束请求，后续死亡、撤离或按钮连点不会再次计算库存。
- 死亡取消原随机预设物品掉落和 1 秒自动回城，直接停在结算界面等待选择。饥饿耗尽在关卡内即致死，不再依赖角色是否切到攻击姿态。
- 结算期间停止角色移动、射击、拾取和饥饿消耗，暂停游戏时间；界面淡入和输入继续使用非缩放时间。
- 结算固定显示背包快照、食材净变化、采集量及拥有总量、时长、击杀数，支持新菜谱/宠物条目。负食材变化显示红字，未获得的奖励类别隐藏。
- “重新探索”顺序卸载旧关卡后再加载同名关卡，保留食材、重置本局统计，创建新玩家与场景实例，重新绑定相机、标题、宠物和战斗数值。
- “返回小镇”卸载关卡，恢复地面场景、相机、标题、角色控制与地图入口。
- 切换期间两个按钮锁定。加载或新局数据准备失败时，保留原结果，重新暂停并恢复按钮，显示错误状态。
- 结算使用独立 Overlay Canvas 与专用 EventSystem，不依赖旧关卡的相机或输入对象。隐藏面板后恢复仍存在的场景输入系统。
- 修复连续重试/回城造成背包入场动画重叠：取消旧的子动画并恢复位置、缩放和透明度，复用 CanvasGroup，不由先结束的动画销毁后续动画正在使用的组件。

## 交付文件

项目目录：`extraction-shooter/UnityProject/ExtractionShooter`。

| 文件/模块 | 职责 |
| --- | --- |
| `Assets/Scripts/Bag/RunEndFlow.cs` | 探索、结算、显示结果和切场景的状态门禁 |
| `Assets/Scripts/Manager/RunSessionManager.cs` | 一次性结束、固定结果、时停与两个目的地的协调 |
| `Assets/Scripts/Manager/LevelManager.cs` | 顺序重载、场景范围引用恢复、单次结果回调 |
| `Assets/Scripts/UI/SettlementUIController.cs` | 只读结果展示、按钮和独立输入接管 |
| `Assets/Editor/SettlementPanelBuilder.cs` | 可重复生成结算预制体及按钮 Sprite 资源 |
| `Assets/Resources/UI/SettlementPanel.prefab` | 已生成并可运行时加载的结算面板 |
| `Assets/Resources/UI/SettlementButtonLight.asset`、`SettlementButtonDark.asset` | 引用原按钮纹理的持久化 Sprite，不改变原 PNG 导入配置 |

`RunSessionManager` 随原 LevelManager 初始化。正常游戏中不需要手动拖拽面板到场景；首次结算从 Resources 加载预制体。

## 当前阶段的边界

第二批交付时，死亡暂时沿用旧全损规则。第三批已移除该临时方法，接入比例分配、死亡箱和跨局舔包；原第二批回归用例也更新为三份食材死亡保留一份、净变化为 `-2`。

正式 UI 美术继续在后续批次完善：宠物目前使用名称条目；木材仍引用当前资源表中的旧南瓜样式图标，需与美术确认正确资源；食材/采集物展示细节与击杀字段的最终口径仍见主计划。

当前关卡重载会刷新其生成对象，生成器按原流程继续预热。加载完成指玩家、相机、标题与数据已就绪，不表示所有随机生成物已经生成完毕。
