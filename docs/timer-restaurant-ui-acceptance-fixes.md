# 餐厅第一批：界面验收反馈修复

日期：2026-10-21。根据四项截图反馈完成。

## 修复结果

1. **制作入口与队列可见。** 原有队列槽位仍连接业务，但场景保存的尺寸和位置归零。恢复五格布局及图标、数量位置；点击顶部制作区可以打开菜谱，右下角菜谱入口继续可用。补上进店期间隐藏旧小镇覆盖层的引用，防止顶部标题拦截鼠标。旧编辑器迁移代码使用 `??` 判断 Unity 原生组件，未识别 Unity 的假空对象，导致缺失的 CanvasGroup 未创建；已改为 Unity 空值判断。
2. **餐厅地面恢复。** 木地板在 SceneGround 层，而周边草地仍在 Default 层，后者整体覆盖了地板。草地改为同一地面层内更低排序，保留现有餐厅背景与家具布局。
3. **删除旧导航。** 从 UpGround 删除 `MainUI/MainTab` 整组废弃导航及其按钮节点。真实食材背包 `MainUI/Bag` 保留，转存完成后隐藏，退出餐厅恢复。
4. **货币栏去重。** 删除餐厅 HUD 的 MoneyPanel、MoneyStrip、SecondaryStrip、CoinIcon、Money 节点及重复绑定，保留现有无底板货币栏。金币使用现有餐厅新版图标；木材复用现有结算资源目录中的木材图标。没有新增固定两格面板，也未提前虚构尚未配置的货币种类。

## 验证

- Unity 2022.3.62f2c1，独立验证工程 `L:/料理地牢/.validation/Batch1`。
- `tests/RestaurantUiAcceptance.cs` 使用 EventSystem 射线检查和 PointerDown/PointerUp/PointerClick 事件，验证顶部入口、右下角菜谱、真实菜品烹饪按钮、退出按钮，未用 `onClick.Invoke()` 代替这条点击链路。
- 实际菜谱点击后检查仓库扣料、等待队列图标和数量、空闲锅开工。为验证等待格，测试临时将锅标为忙碌；为验证失败退款，在投料飞行期间填满队列，确认仅退回该次预留材料，已满队列再次点击不会扣料。
- 检查进店前背包可用、转存后隐藏、退出后恢复，以及入库与退款不会被重复执行。
- `restaurant-ui-integration.log` 同时记录 `RESTAURANT_UI_POINTER_ACCEPTANCE_PASS` 和 `RESTAURANT_STAGE1_UNITY_PASS`。关闭原有首次玩法说明后，又在 `restaurant-ui-visual.log` 完成 UI 验证与画面输出。
- 生成 1280×720、1920×1080、2560×1440 的真实场景渲染，以及等待队列、烹饪与菜单画面。图像保存在 `L:/料理地牢/.validation/restaurant-ui/`。

## 人工验收路线

1. 重新打开保存后的 UpGround 场景并运行；如果首次玩法说明弹出，先点击“关闭”。
2. 从地牢带出食材回到小镇，观察真实食材背包；按原入口交互进入餐厅，转存动画完成后背包隐藏。
3. 确认木地板、围栏背景正常显示，底部五个旧导航按钮消失，左上角只剩无底板货币栏。
4. 点击顶部制作区或右下角菜谱，查看材料数量，选菜并点击“烹饪”。有空闲锅会直接开工；锅忙时，菜品和份数出现在顶部等待格。
5. 材料不足或等待队列已满时再点击，库存不能减少。第一批的退款是“入队失败自动返还”，主动取消等待菜品的 × 按钮仍属于下一批。
6. 使用右下角出门按钮退出，确认真实背包恢复；再次进店不重复入库。

场景和预制体已保存，正常验收不需要手工运行修复工具。`Tools/Modules/Repair Restaurant Acceptance UI` 仅用于在 UpGround 中重复应用相同接线，避免重新生成整个餐厅模块。
