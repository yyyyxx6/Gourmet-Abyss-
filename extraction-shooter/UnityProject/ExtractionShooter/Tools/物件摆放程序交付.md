# 物件摆放程序交付

## 当前规则

- 餐厅、三层战斗统一透视：视线与地面夹角 45°，垂直 FOV 40°；小镇普通状态不变。
- 共享配置：`Assets/Modules/Shared/WorldViewStandard.asset`。餐厅距中心 31、拖拽半径 1.5；战斗距离 27.5、鼠标前瞻上限 3。
- 餐厅保留 XY 玩法平面；战斗使用 XZ。图片模板分别预设 -45°/+45°，对应相同观察角度。不要直接互换坐标或旋转业务根节点。
- 策划《【总】〈料理地牢〉策划文档.xlsx》3C!B7 没有规定度数，要求角度以效果为优先；B8 要求非地面物体垂直镜头方向。B7 原写正交，本次透视及 45° 按后续用户明确确认执行。

## 程序交付内容

| 内容 | 位置/行为 |
|---|---|
| 现有餐厅 | RestaurantWorld 内 42 个物件完成标准分层，保留原布局和业务数量 |
| 可拖用样板 | `Assets/Modules/PlacementSamples/`；TableSet、Stove、ServingTable、Ground 等中性样板 |
| 创建入口 | Project 窗口右键 Sprite/PNG → `场景物件 → 创建场景物件预制体` |
| 修改图片 | 选 PlacementItem，换图/宽度/接地点后点“应用图片配置” |
| 编辑预览 | 同窗口点“预览选中对象/所在模块”；独立预览场景，支持 16:9、4:3、21:9，修改后点刷新 |
| 校验 | `Tools > Modules > Placement > Validate Selected`；选物件、组合或整个 World |

## 使用流程

1. 餐厅：选 `restaurant Module/RestaurantWorld/VisualRoot`，创建窗口选择 XY 样板，点击创建。战斗场景选择父节点，并选择 XZ 地面。
2. 移动物件根节点；桌椅移动 TableSet。地面可在地面平面内旋转，立起图片换方向变体，不随意旋转。
3. 图片宽度以世界单位配置。非地面保持图片宽高比；贴地图片可单独配置宽/深。
4. 检查青色接地点和占地框；有透明留白时修正“图片接地点”，不要移动 Art 伪造落地位置。
5. 打开固定镜头预览，点击刷新。检查原图无额外歪斜、远近大小正确。运行 Game 检查 HUD 和真实业务。
6. 执行校验。物件做好后拖入 Project 保存为预制体；同类外观用预制体变体。不要执行旧 Build/Migration 覆盖人工布局。

树、草等跨模块装饰使用同一套右键创建流程。统一目录下会按源路径归档到 `Assets/Modules/GeneratedPrefabs/Shared/Vegetation/`；餐厅和其他模块则归档到各自模块目录。详细的创建步骤、旧预制体迁移和目录规范见《场景物件预制规范》。

## 谁来定

- 视觉倾角：共享镜头规范决定，程序模板应用；地编只摆位置。固定家具不在运行时写入旋转。
- 根缩放：程序约束为 1；视觉尺寸在 Art 子层。任意父节点缩放会被校验拒绝。
- 接地点：使用脚底/实际落地点，不使用图片中心替代；源图像素位置由素材决定，程序提供独立配置与偏移补偿。旧素材保留原标定点，不自动重切图片。
- 碰撞：程序根据玩法在 Physics 分支配置；不从图片外框自动生成，也不因换图自动缩放。当前餐厅保留旧业务碰撞，没有给展示桌椅擅自新增阻挡或席位。
- 功能锚点：程序注册稳定 ID 并绑定业务；地编移动所属组合。餐厅 37 个原锚点保留 ID/位置，灶台、摆菜台、外卖台的锚点已归属物件。
- 占地框：用于摆位提示，初始样板值不是正式碰撞规格；程序与美术按素材实际尺寸校对，不能把通过结构校验当作占地已签收。

## 一键验证

Unity 保持 MCP 连接，退出 Play 并保存场景。双击 `Tools/Run-PlacementAcceptance-Live.cmd`。

- 第一阶段：编辑态摆放规则、镜头框架、UpGround 和三层战斗真实场景测试。
- 第二阶段：自动进入餐厅、拖拽、UI 拦截、打开菜谱/装修、退出、异常禁用恢复。Game 窗口可看全过程。
- 结果：`Library/CameraAcceptanceResults/Camera-Live-Acceptance-Report.md` 与 `Library/ModuleAcceptance/Report.txt`；餐厅截图同目录。
- 通过后停留在小镇运行态供手动体验。失败不记通过；检查报错后重跑。

普通物件模板不等于新玩法。新经营容量、怪物 AI、方向动画、大型可穿行建筑和完整阴影系统不在本次新增范围。
