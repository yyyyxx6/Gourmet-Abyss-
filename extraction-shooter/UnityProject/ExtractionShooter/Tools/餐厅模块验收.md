# 餐厅模块验收

## 启动

1. Unity 打开 `Assets/Scenes/UpGround.unity`，进入 Play，在餐厅外开始。
2. 打开 `Tools > Modules > Restaurant Acceptance`。
3. 点击“开始逐步验收”，每步体验后点击“验证当前步并进入下一步”；或点击“开始自动验收”。
4. MCP 已连接时，也可运行 `Tools/Run-ModuleAcceptance-Live.ps1`。Game 窗口可看到整个切换过程。

## 通过条件

| 步骤 | 操作 | 通过条件 |
|---|---|---|
| 1 | 进入餐厅 | 地面近宽远窄；灶台、桌椅等手绘图片保持原图造型，没有额外的投影歪斜、梯形变形或宽高压缩；全部素材保留编辑时的角度与缩放；两排三列桌椅；HUD 对齐提供的 UI 参考；不显示旧教学/背包/调试面板 |
| 2 | 按住鼠标中键拖拽 | 地面跟随拖动；持续拖动后停止在配置半径内，松开不继续漂移 |
| 3 | 在菜单按钮上按中键拖拽 | 镜头不移动，按钮可点击 |
| 4 | 点击菜谱、操作旧菜单、点菜单外空白关闭 | 原菜单和经营入口可用；关闭后新 HUD 仍正常 |
| 5 | 点击装修 | 显示原升级面板；不足资源的升级按钮保持禁用；点击面板外空白关闭 |
| 6 | 点出口或 Esc | 恢复小镇原镜头、UI、玩家位置和移动；无残留餐厅镜头请求 |
| 7 | 再次进入并禁用接入组件 | 偏移重置；禁用后退出餐厅并恢复状态 |

自动流程通过真实入口进入，注入拖拽输入，通过 EventSystem 射线命中按钮后发送点击事件。保持 Game 窗口可见，不在运行中切换分辨率。手动模式不注入拖拽，请亲自拖动后再点下一步。不会添加资源或改存档。报告：`Library/ModuleAcceptance/Report.txt`；截图在同目录。

## 补充检查

- 验收窗口“检查独立预制与家具锚点”：在临时预览场景实例化 World/HUD，检查整模块平移、桌椅组移动后锚点跟随；不保存场景。
- 餐厅内点击“测试食材飞行显示”：播放一枚测试图标到现有队列，检查跨 Canvas 坐标及自动清理；不调用入队、不扣食材。结果：`Library/ModuleAcceptance/FlightReport.txt`。
- 相机框架及真实场景回归：运行 `Tools/Run-CameraAcceptance-Live.ps1`，不要同时运行逐步脚本。会切换小镇、地牢并进入/退出 Play。
- 素材摆放：自动流程在进出、拖拽、弹层、禁用恢复的各阶段检查角度/缩放不变；进入、拖拽、UI 拦截阶段还检查全部非地面图片的实际屏幕边框及宽高比例。编辑态测试检查保存后的预制体，在中心、左右/纵深偏移下没有投影变形；另测 XY/XZ、自定义角度和无配置时排序脚本不改 Transform。

## 必须单独人工验收

- 使用测试存档验证食材扣除→排队→烹饪→出菜→顾客就坐→收入、退出重进后的数据保持。自动镜头流程通过不代表经营链路通过。
- 16:9 对照 `Assets/NewVersion/UI/餐厅ui/参考.png`；基准截图为 1920×1080、1440×1080、2560×1080。美术最终确认不由自动测试替代。
- 逐个移动家具组，确认对应席位/操作点同时移动。修改后重新运行，不在 Play 中保存地编变更。
- 装修解锁仍受原存档控制；新增外观桌椅不等于新增经营容量。管理、消息板、新背包交互等待后续业务需求。
