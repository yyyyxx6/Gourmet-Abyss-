# 2.5D 美术与地编对齐方案 V1

状态：2026-09-06 已按用户确认统一餐厅/战斗为 45°，已落地基础物件模板、编辑预览和校验。操作入口见《物件摆放程序交付.md》。美术造型、最终接地点和占地仍以正式素材签收为准。

## 1. 采用的模式

固定视角 2.5D：透视相机 + 平面地形 + 保持手绘造型的物件图片 + 独立玩法根节点。餐厅、战斗及后续模块共用展示规范，业务功能分别接入。

- 地面：二维纹理铺在世界地面上，由相机产生透视缩短和近大远小；不要求美术制作立体地形模型。
- 人物、怪物、普通家具：图片平面与相机成像面平行，保留图片自身轮廓和宽高比例，仅随深度变化大小。不是让每个物件分别朝向相机所在位置。
- 图中已经画出的桌面、侧面和俯视关系由美术决定，程序不补画顶部，也不消除原图本身的倾斜。
- V1 固定相机俯角和方位，不支持自由环绕。跟随、平移、受控缩放可以保留。改变俯角属于展示规范变更，需重验素材。
- 这是“手绘贴片构成的空间”，不是实体 3D：大型物件的穿行、跨越和复杂遮挡必须拆分或使用空间结构，不能靠一张图片自动解决。

参考依据：《饥荒》开发者公开说明其世界使用 3D 空间，地面采用二维地块，立起物件与地面物件分开处理，立起物件只部分面向相机，视角范围经过取舍。本方案借鉴分类和固定视角原则；为满足本项目“保持手绘原图造型”的要求，普通物件选择完全平行成像面的规则，不声称与《饥荒》实现一致，也不引用未经确认的该游戏镜头参数。

来源：[《饥荒》开发者 Kevin 的渲染说明](https://gamedev.stackexchange.com/questions/44852/how-do-i-render-terrain-in-a-2-5d-perspective-like-in-the-game-dont-starve)。

## 2. 当前参数与建议标准

统一沟通口径：俯角指相机视线与地面的夹角，90° 为正俯视。不要直接比较不同坐标体系下的 Transform X 值。

| 区域 | 当前投影 | 视线与地面夹角 | 垂直 FOV | 距观察中心距离 |
|---|---|---|---|---|
| 餐厅内 | 透视 | 45° | 40° | 31 世界单位 |
| 战斗 Layer1 / Layer2 / Layer3 | 透视 | 45° | 40° | 27.5 世界单位 |
| 小镇普通状态 | 正交 | 保留旧平面展示，不纳入本轮统一 | 不适用 | 沿用场景 |

- 餐厅：`Assets/Modules/Restaurant/RestaurantPerspective.asset`，当前偏离地面法线 45°，与地面夹角同为 45°；零旋转 GroundFrame 下镜头 X 为 -45°（315°）。拖拽半径 1.5 世界单位。
- 战斗：`Assets/Modules/Combat/DungeonPerspective.asset`，`pitch=45`；XZ 地面下镜头 X 为 45°。静止和移动的鼠标前瞻上限均为 3 世界单位。
- 餐厅保留旧 XY 玩法平面，GroundFrame 局部 X 为左右、Y 为纵深、-Z 为高度；战斗使用 XZ 地面、Y 为高度。

**当前标准：与地面夹角 45°、垂直 FOV 40°、固定方位。** 两套镜头引用同一份 `Assets/Modules/Shared/WorldViewStandard.asset`。距离按模块构图配置，不统一为同一个数值。改变共享角度后须重新应用图片配置、校验，再签收，不能只改相机。

新内容以 XZ 地面、Y 高度为标准。旧餐厅通过坐标适配保留玩法平面；地编不得自行旋转场景根节点来迁移坐标。美术不需要把“镜头 45°”机械换成每张图片的绘制角度，顶面比例以签收样板为准。

## 3. 通用预制体规则

模块保持 `World.prefab + HUD.prefab + ModuleDefinition.asset`。World 内使用可重复拖放的物件预制体，不要求把整个餐厅做成不可拆的一张图。

| 物件类型 | 显示方式 | 地编操作 |
|---|---|---|
| 地板、地毯、地面痕迹 | 贴地，接受地面透视 | 摆放、拼接，按地面规则旋转 |
| 人物、怪物、普通家具、植被 | 图片平行成像面，接地点固定 | 拖预制体、移位置；方向用规定图集或变体 |
| 可穿行建筑、长墙、桥、大型遮挡物 | 分段图片或明确的空间结构 | 用专用组合预制体，不用普通单图模板代替 |
| 按钮、背包、经营界面 | 独立屏幕 HUD | 按界面参考和屏幕锚点排版 |

每个普通物件统一分层：

- `Root`：地面位置、稳定 ID、碰撞和业务；缩放为 1，不随镜头旋转。
- `VisualRoot`：仅负责图片平面朝向和视觉尺寸；程序模板预设，地编不手调补偿角度。
- `Art`：图片、动画和翻面；保留源图形状。
- `Contact`：地面接地点，也是视觉定位与遮挡排序依据。
- `Anchors`：座位、交互、发射等功能点，位于逻辑分支，不跟随图片倾斜。

类型、接地点、尺寸和排序策略用配置表达；不根据“餐桌”“灶台”等名字猜测规则。普通单图按接地点排序，复合物件按明确分段处理遮挡。已有 3D 对象使用自身空间深度，不统一套精灵朝向或排序补丁。

固定视角家具在制作阶段预设图片朝向；动态角色需要对齐时只操作 VisualRoot。两种实现必须满足同一个画面标准，禁止多个组件重复修改朝向。

## 4. 美术交付要求

- 用角色、桌子、灶台、树各一份确定绘制视角、顶面比例、人物与家具尺度；签收后新增素材沿用。
- 地面交付无预烘焙相机透视的正俯视地块或可平铺纹理，另给边缘和转角；不把含家具、墙体的效果图直接铺成地面。
- 物件交付透明背景图片，并标明实际接地点、占地尺寸和必要交互位置；接地点不等于图片画布底边。
- 手绘导入基准 100 PPU、Bilinear；源图清晰度与世界尺寸一并验收。已有素材不视为已全部符合该标准，像素临时素材不作为正式手绘导入参考。
- 左右或前后不同外观用方向图或预制体变体；不靠随意旋转整张图片制造不存在的侧面。
- 只对独立运动、独立遮挡或可穿行部分拆图；普通桌子不强制拆桌面、桌腿。
- 物体自身明暗由美术保留；地面投影单独处理，不烘进角色动画。程序接触阴影可作为后续独立能力，当前不承诺已有完整光照投影系统。

## 5. 地编操作与工具交付

地编流程：选合格模板 → 换图或选变体 → 在布局视图摆位置 → 同时看固定游戏镜头预览 → 执行校验 → 提交布局。

- 2D Scene 视图只作为摆位辅助。透视游戏画面会改变位置间距和远近尺寸，不能要求整张布局与正交编辑视图像素一致。
- 已合格物件无须逐个调图片角度。桌椅组合移动根节点，接地点与逻辑锚点一起移动；不单独挪图片假装改变占地。
- 只在模板开放的范围调整尺寸；图片层缩放不自动修改碰撞、座位距离，需校验对应占地。
- 现有餐厅的一次性 Build/Migration 工具不是日常地编工具，不能重复执行覆盖人工布局。

程序在批量地编前必须交付：物件模板及变体、统一镜头样板场景、无需进入运行即可看到的游戏视角预览、配置校验入口和清晰报错。校验至少覆盖接地点、图片朝向、非法根缩放、缺失引用、重复 ID、占地与锚点关系。

当前已有：World/HUD 分离、共享 45° 镜头规范、餐厅 42 个标准摆放物件、10 份中性示例预制体、创建/换图/预览/校验入口，以及接地点、投影、逻辑隔离和真实场景测试。导入比例与正式占地不自动猜测；大型空间建筑、完整角色方向动画、地面投影和新经营功能不属于普通图片模板能力。

## 6. 签收门槛

先做一块样板：同一桌子分别放在左、中、右、近、远位置，加入角色、树、地毯及可绕行遮挡；分别在餐厅与战斗接入验证。

1. 同一图片在各位置保留原图轮廓、宽高比例，无新增歪斜；大小随距离合理变化。
2. 地面纹理有一致透视，没有原图透视与相机透视叠加造成的二次变形。
3. 角色绕桌行走，接地点、碰撞、前后遮挡和交互位置一致；不漂浮、不穿帮。
4. 镜头平移至允许边界、角色移动及界面开关时，图片朝向稳定；瞄准、交互和 UI 输入不受影响。
5. 16:9 完成构图签收；4:3 和超宽屏检查裁切、边缘物件、HUD 遮挡。HUD 不受世界透视影响。
6. 美术签收造型与尺度，地编签收操作流程，程序签收投影与功能。自动测试通过不能替代画面签收。

执行顺序：样板确认 → 冻结镜头与素材规范 → 补齐模板/预览/校验 → 适配餐厅并回归战斗 → 批量出图和地编。样板签收前，不要求美术批量返工。
